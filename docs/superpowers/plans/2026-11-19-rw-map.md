# `fs.rw_map` / `fs.ro_map` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a profile mount a host path at a different path inside the sandbox, writable
(`[fs.rw_map]`, directories, created if missing) or read-only (`[fs.ro_map]`, files or dirs).

**Architecture:** `build_plan` (in `pithos`) already carries binds as `(mode, src, dest)` and
everything downstream (`check_bind`, `bind_sources`, `open_binds`, deny overlays,
`describe_config`, `SandboxView`) treats `src` and `dest` separately. Mapped entries are added
to that same list with `src != dest`, after new destination checks. Schema and the
`.pithos.toml` refusal live in `config.py`.

**Tech Stack:** Python 3.11 stdlib, `unittest` under `pytest`, bash escape suite.

**Spec:** `docs/superpowers/specs/2026-11-19-rw-map-design.md`

## Global Constraints

- Stdlib only. Match surrounding style; validation errors raise `ConfigError` naming the key
  (`fs.rw_map` / `fs.ro_map`) and the path, passed through `clean()`.
- Profiles only: `fs.rw_map` and `fs.ro_map` in `.pithos.toml` raise `ConfigError`.
- Destination: passes `check_bind`; not inside the project and does not contain it; not equal
  to, inside, or containing any other bind destination (profile binds, `ro_in_project` pins
  and their ancestors, `copy`, `agent.notice_into`, other map entries). The tmpfs mounts
  (`~`, `/tmp`, ...) are not "other binds": mapped paths are meant to land on `~`.
- Same destination in both tables: `ConfigError`.
- Sources: `realpath`, `check_project_link`, `check_bind`; mounted by fd via `bind_sources`.
- `describe_config` lists destinations only, never sources (already true; keep it).
- Tests: synthetic fixtures under `tests/.tmp/`, fake `HOME`.

## Review Focus

- A destination that is a parent of the project (`"~/src" = ...` with the project in
  `~/src/proj`): must be refused, not mounted over the project. Test in Task 2.
- A map destination on a path an existing `ro` bind shows (e.g. `~/.config/opencode/plugin`
  when `~/.config/opencode` is `ro`): must be refused. Test in Task 2.
- A source holding a deny-glob match (`secret.txt` under an `ro_map` dir with deny
  `"~/data/**/secret*"`): the overlay must land at the mapped destination. Test in Task 2.
- `rw_map` source that exists as a file: refused like `rw_mkdir`. Test in Task 2.
- A child profile redefining a destination replaces the parent's source, and the merged
  result is what gets checked. Test in Task 1.
